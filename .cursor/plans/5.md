Implement the **Agent Detail Page** for the Multi-Agent Studio after the Agent Execution Backend abstraction refactor.

Before coding, inspect the existing codebase and reuse the current architecture, models, hooks, services, UI components, routing, and state-management conventions.

The page must work with the new backend-agnostic agent architecture:

```text id="bpuvab"
Agent
  ↓
AgentBackend
  ↓
AgentRuntime
  ↓
AgentExecutor
  ↓
API / CLI / Local
```

The Agent Detail Page must not assume that every agent is backed by an API provider.

The page should support agents executed through:

* API providers
* CLI runtimes such as Codex CLI, Claude Code, agy
* Local runtimes such as Ollama or LM Studio

Do not implement missing CLI executors here. This page is for configuration, inspection, execution visibility, and management.

---

# 1. Goal

The Agent Detail Page should be the main control and inspection surface for a single agent.

It should answer:

1. What is this agent?
2. What backend executes it?
3. How is it configured?
4. What tools and memory does it use?
5. Where is it used?
6. What has it done in recent executions?
7. Is its execution backend available and healthy?

The page should feel like an engineering/control interface, not a generic CRUD form.

# 39. Definition of Done

The Agent Detail Page is complete when:

1. Existing agents can be opened by ID.
2. General Agent configuration can be viewed and edited.
3. Backend type is visible and editable.
4. API backend configuration works.
5. CLI backend configuration is represented correctly.
6. Local backend configuration is represented correctly.
7. Backend health/auth status can be displayed when supported.
8. Execution policy can be viewed/edited.
9. Secrets are never exposed in frontend state.
10. Tools can be inspected and managed.
11. Memory configuration can be inspected.
12. Workflow usage can be inspected.
13. Agent entity remains separate from graph-node instances.
14. Real Run history is reused.
15. Real RunEvents and Execution Timeline are reused.
16. Execution errors are inspectable.
17. The page does not depend on LangGraph internals.
18. The page does not depend on specific AgentExecutor implementations.
19. No mock-only parallel architecture is introduced.
20. Future Codex CLI / Claude Code / agy executors can be added without redesigning this page.

Before coding, first inspect the current implementation and identify the existing models, services, hooks, runtime abstractions, and components that should be reused.

Prefer incremental integration over rewriting working functionality from Phases 1–4.
