Implement **Phase 10 — Deep Observability, Langfuse Tracing & Evaluation Foundation** for the Multi-Agent Platform.

This is primarily a **backend/runtime instrumentation phase**.

Do NOT build another observability product inside the web application.

We already have operational observability through the existing:

* `Run`
* `RunEvent`
* Execution Timeline
* workflow/node status
* agent status
* errors
* tool execution events
* memory events
* human approval events

The purpose of Phase 10 is different:

> Add deep execution tracing for LLM calls, agents, tools, memory operations, model usage, latency, cost, and future evaluations while preserving the existing Studio as the operational control plane.

The intended separation is:

```text
Multi-Agent Studio
= Control Plane + Operational Observability

Langfuse
= Deep Tracing + LLM Observability + Cost + Evaluation
```

Do not duplicate Langfuse inside our application.

---

As of this phase, prefer the current OpenTelemetry-based Langfuse JS/TS architecture rather than legacy Langfuse tracing APIs.

Do not introduce deprecated Langfuse SDK patterns.

Produce a concise implementation plan before modifying the repository.

# 2. Core Architecture

Target architecture:

```text
                        Engineering Task
                               │
                               ▼
                         Workflow Run
                               │
                               ▼
                         LangGraph Runtime
                               │
                ┌──────────────┼──────────────┐
                ▼              ▼              ▼
          AgentRuntime     Tool Runtime     Memory
                │              │              │
                ▼              ▼              ▼
          AgentExecutor     Tool Calls      Retrieval
                │
        ┌───────┼────────┐
        ▼       ▼        ▼
       API     CLI      Local
        │       │        │
        └───────┼────────┘
                ▼
       OpenTelemetry / Langfuse
                │
                ▼
          Deep Trace Tree
```

Existing operational path remains:

```text
Runtime
   ↓
RunEvent
   ↓
SSE
   ↓
Execution Timeline
```

These are complementary systems.

Do NOT replace `RunEvent` with Langfuse.

Do NOT make the frontend dependent on Langfuse for basic execution status.

# 3. Critical Boundary

Maintain this separation:

```text
Run / RunEvent
    =
application/domain execution history

Langfuse Trace / Observation
    =
deep telemetry
```

A workflow must still work if Langfuse is:

* disabled
* unavailable
* misconfigured
* temporarily unreachable

Observability failure must NOT fail workflow execution.

This requirement is mandatory.

---

# 4. OpenTelemetry First

Prefer an OpenTelemetry-based instrumentation architecture.

Conceptually:

```text
Application Runtime
       ↓
OpenTelemetry
       ↓
LangfuseSpanProcessor
       ↓
Langfuse
```

Avoid tightly coupling business logic directly to Langfuse everywhere.

Where practical, instrument stable runtime boundaries instead of sprinkling vendor-specific calls throughout the codebase.

Langfuse-specific initialization should live in infrastructure/bootstrap code.

# 5. Observability Abstraction

Do not create a huge generic telemetry framework.

However, avoid direct Langfuse calls throughout:

```text
AgentRuntime
ToolRuntime
MemoryService
WorkflowCompiler
API routes
```

Prefer a small application-facing observability boundary if needed.

Conceptually:

```ts
interface ExecutionTelemetry {
  withWorkflow<T>(
    context: WorkflowTelemetryContext,
    fn: () => Promise<T>
  ): Promise<T>;

  withAgent<T>(
    context: AgentTelemetryContext,
    fn: () => Promise<T>
  ): Promise<T>;

  withTool<T>(
    context: ToolTelemetryContext,
    fn: () => Promise<T>
  ): Promise<T>;

  withMemory<T>(
    context: MemoryTelemetryContext,
    fn: () => Promise<T>
  ): Promise<T>;
}
```

Do NOT blindly implement this exact interface if OpenTelemetry context/span helpers already provide a cleaner integration.

The goal is:

```text
domain/runtime
      ↓
stable instrumentation boundary
      ↓
OTel / Langfuse
```

not abstraction for abstraction's sake.

# 6. One Workflow Run = One Correlated Trace

Each workflow Run should be identifiable as one logical trace.

For example:

```text
Run #run_123
│
├── Planner Agent
│
│   ├── memory retrieval
│   ├── LLM generation
│   └── output processing
│
├── Research Agent
│
│   ├── search tool
│   ├── LLM generation
│   └── memory write
│
├── Coder Agent
│
│   ├── repository read
│   ├── model generation
│   ├── filesystem tool
│   ├── shell command
│   └── model generation
│
└── Reviewer Agent
    ├── context retrieval
    └── generation
```

Do not generate unrelated root traces for every internal operation when they belong to the same workflow execution.

Preserve parent-child relationships.

# 8. Trace Context Propagation

Ensure trace context survives:

* async/await
* LangGraph node execution
* AgentRuntime
* AgentExecutor
* tool calls
* memory retrieval
* parallel branches
* retries

Parallel branches must create correct sibling/child observations rather than unrelated traces.

Be especially careful with async context propagation.

Use OpenTelemetry context semantics rather than global mutable variables.

Never use something like:

```ts
let currentRunId;
let currentTrace;
```

as process-global execution state.

Multiple workflows may execute concurrently.

Do not force every operation into a generic span if a meaningful observation type exists.

Do not create excessive spans for trivial internal functions.




# 39. RunEvent Relationship

Do NOT copy every Langfuse observation into RunEvent.


```text

  ├── generation
```

# 53. Definition of Done

Phase 10 is complete when:

1. Langfuse/OpenTelemetry instrumentation initializes correctly on the server.
2. It can be completely disabled without affecting execution.
3. Every workflow Run can be correlated to a deep trace.
4. Agent executions appear as meaningful nested observations.
5. API model calls expose model/usage/latency information where available.
6. Tool calls are traceable.
7. Memory retrieval is traceable.
8. Errors are traceable without exposing secrets.
9. Parallel branches preserve correct trace context.
10. Concurrent Runs do not leak context into one another.
11. Token usage is captured when reliably available.
12. Cost is captured when reliably available.
13. Unknown metrics remain unknown rather than fabricated.
14. CLI agents are represented honestly according to available telemetry.
15. Local agents remain compatible.
16. Existing Run/RunEvent/Timeline architecture remains unchanged and functional.
17. Langfuse failure cannot fail a workflow.
18. Telemetry payloads are redacted and size-limited.
19. Langfuse credentials remain server-side.
20. A Run can store/resolve its Langfuse trace reference.
21. Studio can optionally expose "View Deep Trace" without becoming a Langfuse clone.
22. Environment separation is supported.
23. Existing tests/typechecks/builds remain green.
24. Focused observability tests cover correlation, concurrency, failure, redaction, and disabled mode.
25. The architecture is ready for future evaluations without requiring redesign.
